# 调研结论：市场与板块合并

**日期**：2026-10-15  
**依据**：[spec.md](spec.md)、已评审的交互 DEMO、当前仓库代码。只读调研；未调用生产写接口或执行生产迁移。

## 一、存储与共用价位

**决定**：新增 `daily_review_symbol_levels`，主键为 `(archive_date, symbol)`，保存支撑位和压力位文本；新增归档字段 `market_review_json` 保存版本、一级块、二级结构与迁移冲突原文。二级价位正文不在新 JSON 中重复存储，读接口按标的从价位表装配。保留旧两组笔记列及日计划价位列作为历史来源，不批量转换、不删除旧字段。

**原因**：当前日计划按 `(archive_date, account_id, symbol)` 唯一，价位属于账户行（`cloudflare/migrations/019_investment_accounts_action_plan_accounts.sql:34-98`）。市场标的可能没有任何操作计划；以某账户计划为权威不能覆盖这类标的，也不能保证跨账户一致。价位仍为用户多行文本，不解析为价格带明细，不新增行情或交易数据源。

**备选**：

- 以第一条账户计划为权威：依赖账户排序，删除计划可能丢价位，不采用。
- 在新市场 JSON 中存价位：可以覆盖无账户标的，但更新计划时需重写整份 JSON，查询和隔日隔离更难，未采用。
- 为支撑、压力分别建表：没有独立生命周期，拆表无收益。

**字段存在语义**：价位表中一行存在即表示两个字段均已明确保存，空字符串也是权威值；不存在时才使用历史来源。不能对已保存空字符串使用 `||` 或 `COALESCE(NULLIF(...,''),旧值)` 恢复旧内容。新市场 JSON 的 `NULL` 是尚未保存；`blocks: []` 是明确清空。

## 二、历史归并与价位冲突

**决定**：用纯函数生成旧记录的展示投影，GET 不写库。用户显式保存时写新 JSON 与当日价位；DDL 迁移只增结构，不回填全部历史。旧两组内容在原列中保留。

**确定性归属**：

1. 优先匹配目录中的明确代码（如 QQQ、SPY、SOXX）与完整名称/别名；只在候选唯一时关联。代码命中有多标的时不挑最长字符串猜测。
2. 生产样本中明确的“标普500点位”等大盘标题关联 `GSPC`，含判断的原标题以自定义二级“原一级标题”原文保留。
3. 未匹配、宽泛名称有歧义、跨标的标题保留为 `legacy` 块，不猜测 `MU` 等个股来代表存储板块；没有新建 `legacy` 入口。
4. 保持大盘在前、轮动在后，组内顺序不变。重复标的一级不自动合并；已有迁移身份的重复块可保留，新建重复拒绝。
5. 旧二级的常用标题按有限映射识别；未知标题为自定义。单一一级下重复的同类预设，首项作为预设，后项转为自定义并保留原标题/正文；不拼接或丢弃原文。
6. 原标普块中的“国债”二级留在 `GSPC`，不擅自搬入 `TNX`。用户仍可新增 US10Y 标的主题。

**每个字段分别选择初始价位**：已有价位表行最高优先级；否则按市场块展示顺序采用该字段第一份非空价位，再采用账户顺序中第一份非空计划价位。市场与计划冲突优先市场，其余不同的非空候选记录到冲突原文。支撑位与压力位独立选择，不因某来源只有支撑而丢掉另一来源的压力。

**冲突保留**：编辑详情展示采用值、来源和未采用原文；首次保存把这些证据写入 `market_review_json.conflicts`，后续保存保留，不按新的权威价位重新选择旧来源。未关联块的原文由服务端与既有或确定性投影比对，只允许保留、删除或明确关联。

**备选**：批量 UPDATE 历史 JSON 或以模糊/LLM 分类迁移，增加写额度和误关联风险，不采用。

**代码证据**：`normalizeReviewNoteBlocks`（`cloudflare/worker/src/index.js:1004`）；旧 JSON 列迁移 021。迁移 022 已删除纯文本列，当前 Python `save_archive` 与 `initialize_archive_record` 仍引用已删列（`src/db_utils.py:403-499`）；实现时只更新这两个相关字段读写，不做其他 Python 链路重构。

## 三、历史沿用、明确清空与初始化

**决定**：统一解析器区分“保存结构”与“有效展示结构”，bootstrap 可沿用、日期详情只呈现本日持久内容的归并投影。

- 当日新 JSON 非 NULL：直接用它，包括 `blocks: []`；不再从旧列重建主题。已保存价位独立存在，删除主题不删价位。
- 当日新 JSON 为 NULL：各旧字段存在时使用该字段，即使为 `[]`；仅 SQL NULL 的旧字段允许跨日沿用。分别保留两组原有的最近非空 reviewed 来源，允许来源日期不同。
- 先找最近非空新结构日期 N 作为统一沿用基线，再找 N 之后各旧组最近非空日期的内容。较新旧组只替换基线中 `legacyOrigin.group` 对应的那一组，另一组和无 legacyOrigin 的新建主题保留；N 之前的旧组不再覆盖基线。没有新基线时仍独立选两旧组来源。新结构已持久化日期的冻结旧列排除候选。当前旧字段明确保存的内容（含 `[]`）优先于对应组的沿用默认值。
- 例：N 的新文档包含来源 market 的 GSPC、来源 rotation 的 SOXX 和新建 MU；N 之后旧 market 有新判断、最新旧 rotation 在 N 之前。沿用为较新旧 market＋N 的 SOXX＋N 的 MU，不用早期 rotation 覆盖 SOXX。因无损保留出现同标的重复时遵循历史重复规则，不静默合并。
- 来源搜索跳过有效结构为空的中间日；只读解析不把 NULL 回写为 `[]`。
- 沿用只提供目标日默认值；显式保存时写到目标日，不更新来源日。价位初始优先级为目标日已保存行、目标日市场正文、目标日日计划、沿用来源价位。冲突仍保留证据。
- 初始化保持已 reviewed 日期跳过；非 reviewed 重置时，新 JSON 置 NULL，旧列按现有行为置 NULL，不清理既有价位。无日计划时从 live 复制计划；初始化不写 `daily_review_symbol_levels`，当日初值由读投影按上条优先级计算，首次显式保存或首次 live 写入时连同冲突证据一起物化；既有价位行不清理、不覆盖。这样沿用来的市场价位仍按市场优先参与选择，冲突证据不会因初始化提前落行而丢失。

**原因与证据**：当前 bootstrap 在 `cloudflare/worker/src/index.js:1375-1393` 独立查找两组来源；`resolveReviewNoteBlocksWithFallback`（1038-1056）以字段是否非 NULL 控制回填。`getReviewByDate`（1323-1346）与 bootstrap 的行为当前不同，须保留这个接口边界。

**备选**：把 NULL、空字符串和 `[]` 统一为空再自动回填，会覆盖用户清空意图，不采用。

## 四、复盘日与实时计划的同步

**决定**：保留实时计划集合与最新归档日双向同步的现有业务范围；价位一致性纳入该同步，不另造跨日同步规则。

- 最新日期是 `MAX(daily_review_archive.archive_date)`，不是最新 reviewed 日期；实时编辑即便最新日已完成仍会回写该日。明确保持现状，不在本需求改变。
- 有最新日时，实时计划的价位读接口投影该日共用值；表内原价位列作为实时镜像和无复盘日时的承载，不作为已保存日期价位的第二权威。
- 单项实时价位修改只覆盖请求明确修改的字段，并同步该标的其他账户的实时镜像及最新日共用价位；其他账户的动作、仓位、思考均不变。
- 新账户同标的建计划若未提交价位，读取既有共用值；明确提交价位则更新共用值。排序或修改其他字段，不用旧请求中的价位镜像覆盖新值。前端 live 保存要按实际变更生成价位字段。
- 实时删除只删除计划及其日计划镜像，保留日期价位与市场主题。没有实际价位修改时不恢复用户已删的市场主题；真正填价位时才补主题/二级。
- 尚无复盘日时不制造日期；GET 对每个字段按账户展示顺序取第一份非空 live 原值，所有同标的账户统一投影并返回差异提示、零写库。用户明确修改时同步该字段的同标的 live 原列；新日的价位行在首次保存或首次 live 写入时物化，初始化不写。
- 首次针对未物化最新日的 live 写入，先按市场优先规则计算并冻结旧初始文档/冲突原文，再叠加本次显式价位补丁；两者和 live/日计划更新同一 batch 提交。冻结内容取写入前的有效展示结构（与 bootstrap 相同，含跨日沿用，并记录 sourceDates），等同用户此刻打开该日复盘看到的默认内容，不能只按本日 NULL 字段物化成 `blocks: []` 而永久挡住沿用。不能先改 live 镜像、再拿改后的值重算首次迁移证据。非价位 live 编辑也保持相同的一次物化入口，后续不重新归并。
- 最新日市场保存即使没有提交 `actionPlans`，也更新同标的实时价位镜像；历史日保存不改 live。

**原因与证据**：`syncLatestDailyFromLive`（`cloudflare/worker/src/index.js:2534-2538`）会整集回写最新日；`saveReviewDraft`（2916-3009）只有提交计划数组才把最新日日计划同步到 live；`initializeReview`（3243 起）仅日计划为空时复制。新方案必须覆盖这些入口，否则下一次 live 编辑会复活旧价位。

**备选**：为 live 再建无日期标的价位表，增加第二套模型且当前无必要；禁止已完成日回写属于另一个需求，均不采用。

## 五、接口与原子保存

**决定**：复用现有复盘 POST，新增 `marketReview` 聚合字段（结构替换＋价位补丁），不增加二级或价位单项网络 API。新 frontend 只发送新字段，旧请求字段返回明确的升级错误，不维护双写兼容层；旧数据库列仍用于只读迁移。

- `marketReview.blocks` 保存当前完整结构；`marketReview.levels` 只提交本次实际修改或首次物化的价位，字段省略不变、空字符串清空。
- 操作计划的 `supportLevels`、`resistanceLevels` 在新读响应仍存在，供原有表格与导出消费；复盘计划保存不将其视为独立输入，以 `marketReview.levels` 为准。
- 复盘 POST 提交了 `marketReview.blocks` 时，blocks 即最终结构，服务端不追加主题/二级；页面在用户填写计划价位时已在草稿中补齐，用户随后在草稿中删除的主题不会被服务端补回。levels 补丁照常写入（价位可独立于主题存在）。服务端补齐只用于未提交 blocks 的写入口：live CRUD、省略 marketReview 的复盘保存、Python 写入，且仅在实际非空价位修改时发生；清空补丁、首次物化以及未变化计划镜像都不恢复用户已删的价位/主题。
- 保存读阶段同时拿当前归档、目录和当日价位等必要信息；批量校验，不逐标的查询。自定义空标题、未知预设、不合法结构返回 400；新增重复/违规更换返回 409。沿用历史缺失目录身份可继续编辑，但不可凭请求新建不存在的标的。
- 当前多张表同批写，但 `runWriteBatches` 每 100 语句分块，不是跨批事务（`cloudflare/worker/src/index.js:2013-2019`）。本功能的完整保存必须用一个 D1 `batch`；用 `json_each(?)` 集合 UPSERT/成员删除压缩新增价位与相关计划写入，避免大请求跨批半写。所有 SQL 参数化；迁移转换不触发 LLM/Yahoo 请求。
- 新增集合 SQL 必须经 SQLite harness 和实际本地 D1验证，尤其 `INSERT ... SELECT ... WHERE ... ON CONFLICT` 的语法歧义。每语句绑定参数不超过 100，SQL 100KB 限制不通过拼接用户数据规避。

**备选**：每改一栏 POST 或旧新字段双写，分别引入网络往返与分叉，不采用。

## 六、US10Y 身份

**决定**：系统键保持 `TNX`，Yahoo 仍为 `^TNX`；目录响应增加推导的 `displayCode`（一般等于 symbol，TNX 为 US10Y），并在展示搜索别名中包含 US10Y。选择提交仍为 `symbol: TNX`。标的管理显示 US10Y 并提示内部代码 TNX；目录编辑表单保持原系统键。

**原因**：当前代码改名会更新部分关系但漏掉实时计划（`cloudflare/worker/src/index.js:3600-3674`）；本需求无需修改代码身份、采集或全部数据关系。GET 添加展示值不写目录；硬删除后依赖块的 identity snapshot 继续展示。

**备选**：TNX 重命名、另增 US10Y 行、Yahoo 改别的代码，均扩大范围并引入双身份，未采用。既有 `/api/symbols/resolve` 会调用 LLM/Yahoo（3695 起），不能用于本地旧笔记归属；现有导出 `resolveRotationSymbol` 会退回未知 token（`cloudflare/web/zone-export.js:75-76`），也不能直接用于严格迁移。

## 七、桌面 UI 与导出

**决定**：继续 vanilla JS，复用真实操作计划的表格、工具栏、标的搜索和详情样式，不把 Canvas 的 React 引入生产。只新增一个纯 ES module `cloudflare/web/market-review-model.js`，供 Worker 和浏览器共用结构常量/归并规则；无组件库和新状态框架。

- 合并步骤、目录、完成校验为“市场与板块”；保留其他步骤顺序和必选/可选规则。
- 表格：标的、支撑位、压力位、思考、其他分析；详情采用已评审右侧面板。真实操作计划详情目前是居中 modal（`cloudflare/web/styles.css:3527-3533`），只复用其字段/按钮视觉，不声称现有 CSS 本身已经是右侧抽屉。
- 无“市场标的”重复分组；工具栏在标题右侧；每标的左侧短浅蓝竖条，选中深蓝；无外围连续蓝线。仅桌面设计和验收。
- 只读/编辑基于原 reviewed/editing 状态；详情“完成编辑”只更新本地草稿，顶部保存才持久化，与复盘操作计划一致。
- 导出统一从新 blocks/levels 读取身份，不再靠标题猜标的。普通标的仍压力在前、支撑在后，相同区间去重。
- 保留 GSPC 原有 `SPX,ES1!,ES` 专用模板、支撑传参顺序、负伽马/加速下跌窄区间，仍不从普通压力段落生成该模板。此字符串只是既有导出目标，不新增指数或期货跟踪标的。
- 未关联历史块仅在旧行为可唯一识别时参与既有导出；不推测跨标的段落。`key_levels` 不加入新价位模型，不清理历史原值。

**证据**：`cloudflare/web/app.js:2315-2411,2698-2782,3017-3030`；`cloudflare/web/zone-export.js:213-249,317-383`。列表主线提取（Worker 967-986）、快照（3386-3408）同样必须识别新结构；快照需复制当时价位，不能以后回查当前值。

## 八、验证与已知文档漂移

**决定**：基于全部正式迁移的真实 SQLite SQL 测试，加 `APP_ENV=test` 的本地 Worker/D1 与桌面 Chrome 验证；测试文件和夹具均在 `tests/`。不使用生产复盘 POST、生产夹具重置或远程写基准。

**已执行的规划基线**：`tests/review_completion_roundtrips.test.mjs` 通过 1/1；`tests/integration/migrations_fresh_replay.py` PASS。当前守门为 normal ≤7、large ≤9（前者 50 新闻/20 计划，后者 200 新闻/40 计划），不是早期文档的 11/17；当前 batch 分块是 100，不是 50。基线测试不代表新功能实现完成。精确计数补测被权限检查拦截，未重试。

**范围**：不补写未配置的宪章，不修改 skill/配置；集成测试标准中的 master 旧称与 CLAUDE.md 当前 main/test 规则冲突时，以当前配置和 CLAUDE.md 为准。`tests/schema.sql` 过时，新测试使用正式迁移而非复制旧 DDL。现有少数 smoke 硬编码生产名称但带 `--local`；实现阶段改为读取本地测试配置，不能混用两个本地状态目录。

**Phase 0 结论**：存储、冲突、沿用、实时同步、接口、展示身份与验证入口已确定，无未解决设计澄清项。具体结构见 [data-model.md](data-model.md)，契约见 [contracts/review-api.md](contracts/review-api.md)。
